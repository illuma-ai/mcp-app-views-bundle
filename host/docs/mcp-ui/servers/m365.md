# Server: Microsoft 365 (mail and calendar views)

**Package.** Fork of the open-source Microsoft 365 MCP server at
`C:\Projects\Chat\Texas-Capital-Clone\softeria-ms-365-mcp`, branch `feat/outlook-review-views`. The views
are described in its `docs/interactive-views.md`.

**Build and start** (from that folder; scripts from its `package.json`, flags from its README):

```
npm install
npm run build              # tsup (the view generator runs via the generate scripts)
node dist/index.js --http 3000 --org-mode    # HTTP mode serves /mcp
```

The tool set is chosen with `--enabled-tools '<regex>'` or `--enabled-tools-file`, and the permission
boundary with `--allowed-scopes` (the setup script's comments say the server runs with the list in
`m365-setup/scopes.outlook.txt`). The exact `--enabled-tools` value used locally is not recorded in either
repository: copy it from the running process before transferring.

**Host block** (`librechat.yaml`; file name per brand in [../TRANSFER.md](../TRANSFER.md)):

```yaml
mcpServers:
  m365:
    type: streamable-http
    url: http://localhost:3000/mcp
    requiresOAuth: true
    timeout: 120000
mcpSettings:
  allowedAddresses:
    - 'localhost:3000'
endpoints:
  agents:
    toolApproval:
      allow:
        - 'list-*_mcp_m365'
        - 'get-*_mcp_m365'
        - 'create-*-draft*_mcp_m365'
        - 'create-draft-email_mcp_m365'
        - 'update-mail-message_mcp_m365'
      ask:
        - 'send-mail_mcp_m365'
        - 'send-draft-message_mcp_m365'
```

Merge the `allow` and `ask` entries into the shared lists; the local file also lists other servers there.

**Entra app registration** (script `m365-setup/entra-app.sh`, dry run by default; no secrets here):

- platform Web, with a client secret held by the server; delegated Graph permissions only
  (`m365-setup/scopes.outlook.txt`: openid, profile, offline_access, User.Read, Mail.ReadWrite, Mail.Send,
  Calendars.ReadWrite); tenant admin consent where required
- redirect URIs: `<chat origin>/api/mcp/m365/oauth/callback` (local: `http://localhost:3080/...`) and the
  server's own `<server origin>/callback`
- server environment: `MS365_MCP_CLIENT_ID`, `MS365_MCP_TENANT_ID`, `MS365_MCP_CLIENT_SECRET` (from your
  registration; the script writes them to `m365-setup/secrets/m365.env`, which is never committed)
- each user signs in with Microsoft through the chat app's per-server OAuth flow
